Making of · Process notes

How this site
was built.

The portfolio is designed like the systems it presents: every section is a layer a request passes through, every interactive piece explains a real idea, and nothing claims more than the evidence supports.

01 / Principles

Rules the design
had to follow.

  1. Show, don’t claim.BoundaryLab’s policy explorer and its 3D request trace let visitors run an idea instead of reading about it, and say plainly what they are and what they are not.
  2. Evidence over adjectives.Project status is stated honestly: pre-release, research, or a public experience without live booking. The Aetheris result links to the CI run it describes.
  3. Motion is optional.Operating-system reduced-motion settings and ?motion=off give a calm, static page. Everything still works without JavaScript.
  4. Own every byte.Fonts, images and libraries are self-hosted. A strict Content Security Policy allows no third-party scripts, CDNs or eval.

03 / Ideas that were replaced

What changed,
and why.

“Welcome to my portfolio.”“Backend systems. Built with intent.”

A generic greeting told visitors nothing. The new line says what I build in four words.

A one-rule permission exampleA working policy explorer

Four identities, two resources, two operations and two policies, with a trace that shows which check decided.

Vertical hero shuttersAn uninterrupted portrait

The shutters competed with the photograph. Removing them made the first screen calmer and faster.

Visible Motion and pause togglesSystem preferences

Reduced motion now comes from the operating system and ?motion=off, without extra controls on every visit.

A contact business cardA concise invitation

Email, availability and links do the job with less to read.

Scene parsed while scrollingIdle-time 3D loading

The Three.js bundle now loads while the visitor is reading, not as they scroll into Work.

04 / Technology

Chosen for
the job.

Technology used on this site
PageStatic HTML and CSS served by Vercel, with matching security headers for a second host.
IslandsReact and TypeScript components (navigation, introduction, lanyard, footer, command menu) sharing one React runtime.
MotionGSAP and ScrollTrigger for scroll storytelling, Lenis for smooth scrolling, the Web Animations API for small loops.
3DThree.js r187 (WebGL) for the BoundaryLab request trace, bundled and tree-shaken with Bun; CSS 3D for the system model and lanyard.
SoundOptional Web Audio tones, synthesised in the browser, off by default.
QualityNode tests, a quality gate for budgets, links and headers, and CI that rebuilds the React bundles byte-for-byte.
